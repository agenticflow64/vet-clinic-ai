# AI-ассистент ветеринарной клиники «Каштанка» — демо-стенд

**Внимание, честная формулировка.** Сайт ветеринарной клиники
[kashtanka64.ru](https://kashtanka64.ru) — реальный продовый проект
(fullstack: Kotlin/Quarkus + Astro + k8s). Этот репозиторий — **демо-стенд
AI-ассистента**, отдельного сервиса, который *готов к встраиванию* в сайт
клиники (см. [docs/integration.md](docs/integration.md)). Ассистент заказчику
не внедрялся, в проде не используется. Все цифры ниже — локальные замеры
на демо-стенде.

## Задача

Показать, как на реальном сайте ветклиники может работать AI-виджет:
посетитель пишет в чат и получает помощь по трём сценариям в одном диалоге:

1. **Вопросы по услугам и ценам** — RAG по прайсу клиники: ответ называет
   конкретную услугу и цену из прайс-листа.
2. **Предварительный триаж** — владелец описывает состояние питомца,
   ассистент оценивает срочность («срочно к врачу / приём в ближайшие дни /
   планово»), задаёт 1–2 уточняющих вопроса. Всегда с дисклеймером:
   *не заменяет консультацию ветеринара*.
3. **Запись на приём** — ассистент извлекает из диалога структурированные
   данные (кличка, вид животного, услуга, желаемое время, телефон) и создаёт
   заявку; заявки видны на админ-странице со статусами.

## Решение

Python + FastAPI + SQLite, минимум зависимостей. Никаких векторных БД и
брокеров — корпус крошечный, а демо должно собираться за минуты.

```
Прайс (xlsx, только чтение)  ──convert──▶  data/services.json (347 услуг)
                                                    │
                                              ingest + bge-m3 (GPU)
                                                    ▼
                                        SQLite: услуги + эмбеддинги + кэш
                                                    │
   виджет (iframe/embed.js) ──▶ FastAPI ──▶ ассистент: классификатор намерения
   админка заявок    ◀─────────────┘          ├─ price  → косинусный поиск → LLM
                                              ├─ triage → LLM + дисклеймер
                                              └─ booking → извлечение полей → заявка
```

### Источник данных

Публичный прайс с сайта: `vet_clinic_pricelist.xlsx` (296 услуг, без категорий)
и лист «Прайс-лист» из `kashtanka.xlsx` (короткий список с «человеческими»
названиями — «Стерилизация кошки» вместо «Овариогистерэктомия кошки»).
Репозиторий клиники не изменяется — файлы только читаются.
`scripts/convert_pricelist.py` конвертирует их в `data/services.json`;
категории назначаются детерминированными правилами по ключевым словам
(`app/categorize.py`, покрыто тестами).

### Почему эмбеддинги локальные, а не API

Эмбеддинги считаются **BAAI/bge-m3** на локальной GPU (RTX 5060 Ti) отдельным
процессом `embeddings_service/` (py3.12 + sentence-transformers). Приложение
(py3.14) ходит к нему по HTTP на `127.0.0.1:8111`, клиент сам поднимает сервис
при необходимости. Так GPU-зависимости (torch) не попадают в окружение
сервиса, а в docker/k8s не нужен GPU-passthrough в контейнер приложения.
Кэш эмбеддингов — в SQLite, повторный ингест бесплатен. Полный ингест
347 услуг — ~5 секунд.

### Почему косинус в Python, а не pgvector

Корпус — 347 векторов по 1024 измерения. Полный перебор — единицы
миллисекунд, любой внешний векторный сервис только добавит задержку и
инфраструктуру. При росте корпуса до десятков тысяч записей переход на
pgvector не меняет интерфейс `search()`.

### Выбор LLM (замеры, демо)

Генерация — только бесплатные модели OpenRouter. Кандидаты прогнаны на
3 типовых промптах × 2 повтора (валидность JSON, русский язык, скорость):

| Модель | Валидный JSON | Медиана | Вывод |
|---|---|---|---|
| nvidia/nemotron-3.5-lightning:free | 6/6 | ~8 с | **основная** |
| nvidia/nemotron-3-ultra-550b-a55b:free | 5/6 | ~4 с | резерв 1 |
| google/gemma-4-31b-it:free | — | — | резерв 2 (апстрим давал 429) |
| poolside/laguna-s-2.1:free | 2/6 | ~0.7 с | отбракована |

lightning — reasoning-модель, поэтому `max_tokens` держим 2500, иначе ответ
обрезается на рассуждениях. Цепочка fallback настраивается `LLM_MODELS`.

## Результат (демо, локальные замеры)

Живые замеры `scripts/benchmark.py`, отчёт: [docs/benchmark.md](docs/benchmark.md).

- **Поиск по прайсу**: 12 вопросов — top-1 **11/12 (92%)**, top-3 **12/12**.
- **Ответ LLM называет точную цену**: **12/12** (100%).
- **Триаж**: 3 сценария (не может пописать / хромает / плановая вакцинация) —
  срочность верна **3/3**.
- **Диалог → заявка end-to-end** (4 реплики, от «хочу записаться» до записи
  в базе): **~215 с** — это цена бесплатного тарифа: reasoning-модель отвечает
  15–25 с на вызов, на реплику нужно 2 вызова (классификация + генерация),
  плюс редкие пустые ответы с перебором fallback-цепочки. Одна реплика чата
  в среднем — 15–30 с. На платной модели это секунды.
- Тесты pytest: **30 passed** (юнит: категоризатор, промпты, парсинг JSON,
  поля заявки; интеграционные: офлайн-RAG находит услугу, диалог создаёт
  заявку, админка меняет статус).

## Запуск за 3 команды

```bash
cd vet-clinic-ai
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt  # (1) окружение
set -a; source .env; set +a                                          # (2) ключи OpenRouter
.venv/bin/python scripts/ingest.py && .venv/bin/uvicorn app.main:app --port 8010  # (3) ингест + сервер
```

GPU-сервис эмбеддингов поднимется автоматически при первом обращении
(окружение: `uv venv embeddings_service/.venv --python 3.12 &&
uv pip install --python embeddings_service/.venv/bin/python sentence-transformers`).

Страницы:

- `/demo` — демо-страница с шапкой в стиле сайта клиники и встроенным виджетом
- `/widget` — чистый чат-виджет (для iframe)
- `/admin` — заявки на приём со статусами
- `/api/docs` — OpenAPI

Тесты: `.venv/bin/python -m pytest tests/ -q` (полностью офлайн).

## Структура

```
app/            FastAPI-сервис: assistant.py (оркестратор), prompts.py, llm.py,
                embeddings.py (клиент GPU-сервиса), search.py, store.py, categorize.py
embeddings_service/  GPU-сервис эмбеддингов (bge-m3), отдельный процесс и venv
scripts/        convert_pricelist.py, ingest.py, benchmark.py
static/         widget.html, embed.js, demo.html, admin.html
tests/          pytest: юнит + интеграционные (офлайн)
docs/           architecture.md, demo-script.md, integration.md, benchmark.md
data/           services.json (прайс), vetclinic.db (не в git)
```
